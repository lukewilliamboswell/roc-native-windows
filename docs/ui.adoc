= Win32 controls

Import `pf.Win` to use `Win.Ui` for controls, `Win.Files` for files and
`Win.System` for system services. The standalone `pf.Ui` import also
works. Examples in this reference use `Ui` as shorthand for `Win.Ui`.

[#window]
== Windows and dialogs

An ordinary app gets one main window. Use `Ui.window(props, content)` as
the outermost element to set its title, close behaviour, or chrome.
`title` defaults to `AppTitle`, which uses the application's configured
display name. Use `Title(text)` to supply a title from an app signal.

Use `Ui.windows(declarations)` at the root for independent windows sharing
one app store. For example, use `Engine.each` with a stable key per window
and return a `Ui.window` from each row. A managed window requires
`close: Handle(handler)`. The handler runs when the user requests a
close. Remove the declaration to accept the request. Closing the last
independent window ends the app once the turn settles.

`Ui.dialog({ title, open, on_close_request }, content)` mounts an owned
modal dialog while its open signal is true. Its owner is the enclosing
window. Close and Escape request dismissal, and the app accepts by
clearing the open signal. Save and Cancel can update state and dismiss
in one turn. The dialog's controls can set their own default Enter action.
Opening or closing the dialog leaves the owner's layout in place.

[#window-chrome]
== Window chrome

The `status_bar` prop defaults to `NoStatusBar`. Set
`StatusBar({ text, trailing })` to show a primary status signal and
optional trailing panes. A trailing pane takes a text signal and an
optional `width` in device-independent pixels, with a default of 128.
The primary pane fills the remaining width. At narrow widths, trailing
panes drop from the right so the primary status stays available. The bar
stays at the bottom while the window content scrolls.

Set `taskbar_progress` to a `Ui.Progress` signal to reflect work in
the app's Windows taskbar button. It defaults to `Idle` and shares
the in-window indicator's progress modes and normalization. The
taskbar receives the current value when its button becomes available,
including after Explorer recreates it.

[#controls]
== Control reference

Import `pf.Ui` from the Windows platform. The controls receive Roc Signals
values. A handler sends writes to the state the view reads. See the
https://github.com/lukewilliamboswell/roc-signals[Roc Signals manual]
for state, stores, and worker tasks.

Stack spacing, padding and image dimensions use device-independent pixels.
Set `stack_below` on a horizontal stack to lay its children out vertically
when the available width in device-independent pixels drops below that
value. The default of 0 keeps a horizontal layout at every width.
An image path is relative to the app's `assets/` directory. Give each
interactive control a meaningful caption or label. The test runner uses
those names to locate controls.
See xref:accessibility.adoc#labels-and-graphics[the accessibility chapter]
for field labels, descriptions and status announcements.

Each `Ui.Choice` contains a string `key` and `label`. Use a nonempty key
unique within the control and keep it stable when renaming or reordering
options. Visible labels may repeat. The drop-down and list box take
choice and selection signals. A selected key that has no corresponding
choice is shown as an empty selection. Their `on_select` handlers receive
`Ui.Selection.Selected(key)` or `Ui.Selection.NoSelection`.

A radio group needs at least one choice and a selected key from its
static choices. Its `on_select` handler receives the selected string key.
These controls show the selection supplied by the app. A user choice
becomes the displayed selection when the handler updates that signal.

`Ui.CivilDate.from_parts({ year, month, day })` validates a Gregorian date
from 1753-01-01 through 9999-12-31, inclusive. It returns
`YearOutOfRange` or `InvalidCalendarDate` on error. The date picker uses
the Windows short-date format and renders the `NoDate` selection with
its checkbox clear. The typed change handler receives `Date(date)` or
`NoDate`.

`Ui.CivilTime.from_parts({ hour, minute })` accepts clock hours 0–23 and
minutes 0–59 and returns `InvalidClockTime` on error. The time picker
uses the Windows short-time format and renders `NoTime` with its
checkbox clear. The change handler receives `Time(time)` or `NoTime`.
The field displays an example in the Windows short-date or short-time format.
Date input uses four-digit Gregorian years and also accepts ISO `YYYY-MM-DD`.
Time input has minute precision and also accepts 24-hour `HH:MM`.
Enter or a move to another control commits a valid draft. Clearing the
field and committing proposes `NoDate` or `NoTime`. An invalid draft
stays visible with a validation message. Escape restores the committed
value. A handler may decline a proposal and keep the previous value.

The date field also provides a *Choose date* button. In the calendar,
use the arrow keys to move by day or week and Page Up or Page Down to
change month. Enter or Space chooses a date. Escape closes the calendar
and restores focus to *Choose date*.

Both civil types expose `parts()` and `to_iso()`. A date and clock
reading describe calendar fields. To resolve them to an instant,
supply an application policy for timezones, offsets and ambiguous times.

`Ui.tree_view` uses keyed nodes with a `label` and a `parent` of
`Root` or `ChildOf(key)`. Parents can appear anywhere in the node list.
The list orders siblings. Use unique nonempty keys and existing parents.
A tree supports up to 4096 nodes, 64 levels, keys of up to 1024 UTF-8 bytes
and labels of up to 1024 UTF-16 code units.

The `expanded` signal is a set of branch keys. `on_expand` receives a key
and either `Expanded` or `Collapsed`. Write membership and any selection
change in the same handler. If the app keeps a selected descendant when its
branch collapses, the native caret moves to the collapsed ancestor and the
descendant has no visible selection until it is revealed again.

`Ui.tabs(props, page)` displays a native tab strip above the active page.
Use at least one tab with a unique key and supply one of those keys as
`selected`. Pass that same signal to `Engine.switch` to mount the matching
page. If `on_select` declines an intent, the selected tab and page keep
their previous state. Keep drafts or results that should survive a page
switch in app state outside the page's scope.

Use `Ui.Progress.Indeterminate` while work is active and its total is
unknown. `Determinate({ completed, total })` caps completed work at total.
A zero total resolves to `Idle`. The bar and its label keep their layout
space while idle. With client-area animation disabled, an indeterminate
indicator displays steady busy text.

`Ui.file_drop_target(props, content)` accepts an Explorer file drop over
its frame or content. A drop over nested targets goes to the innermost
target. Its `on_files` handler receives the same file capabilities and
refusal count as the file picker. Keep a file picker in the area so users
can also open files with the keyboard.

A multi-file confirmation delivers its files and refusal count in one
event. Cancelling the picker leaves the app's selection alone.
A successful selection holds an open read handle for each accepted file.
A later item at the same path cannot replace that handle's contents.
Reads, hashes, image decoding, and export use the held file. The operating
system may still allow another program to edit that same file in place.
On Windows, `Engine.object_url` returns `Err(Unavailable)` for these
capabilities. Use a file read or image decode to display the contents.

`Ui.folder_button` delivers either `FolderChosen(folder)` or
`FolderRefused(Unavailable)`. Use `folder.name()` for display and
`folder.files({})` in an engine request to obtain up to 16 immediate
ordinary files. Set `limit` to request fewer. Results are ordered by
UTF-16 filename and report a partial listing when the scan or result
limit is reached or an entry is skipped. Enumeration skips subdirectories
and reports reparse points as skipped entries. The returned files support
reading, hashing, and saving a copy. The host keeps their paths private.

[#toolbar]
== Command toolbars

Use `Ui.toolbar({ label }, items)` above the content its commands act on.
Build each command with `Ui.toolbar_button(title, { key, on_press, enabled })`.
Keys are nonempty and unique within the toolbar. The title, enabled state,
and the action's context can follow your Roc state. `on_press` uses the same
click handler as a push button. Insert `Ui.toolbar_separator()` between
command groups.

Use Tab to reach the toolbar, arrow keys to move between commands, and Enter
or Space to activate a command. Commands wrap when the window narrows. Use
short captions that fit at the smallest supported window width.

Both push buttons and toolbar commands can display an ICO beside the
caption. Pass an icon signal such as
`icon: Engine.const(Ui.CommandIcon.IconAsset("reading-list.ico"))`.
Paths are relative to `assets/` and can include subdirectories.
The default `NoIcon` omits the image. A missing or unreadable icon
leaves the command caption and action available.
Windows displays the image at the appropriate size for the window DPI.

[#list-view]
== Report lists

Use `Ui.list_view(props, rows)` to display records with native headers and
single-row selection. Define `columns` with unique nonempty `key` values
and a `heading` for each. The default width, `Auto`, measures the heading
and mounted cells and clamps the result to 48–360 device-independent pixels.
Use `Fixed(width)` for a positive width in device-independent pixels.
The list scrolls independently. Set `visible_rows` to budget space for
1–64 rows. The default is eight.

Build rows with `Ui.list_row({ key }, cells)` and
`Ui.list_cell(value, { column })`. Give each row a stable, unique, nonempty
key and one cell per column. The column key determines where the cell appears.
For dynamic rows, pass the element produced by `Engine.each` or
`Engine.table_view` in the list's child array.

Supply a `selected` signal of type `Ui.Selection` and write its new value
from `on_select`. The selection is `NoSelection` or `Selected(key)`.
When the key is outside the mounted rows, the highlight clears.
Use `on_activate: Handle(handler)` to respond to Enter or a double-click
on a row, even if it is already selected. Use
`on_column_press: Handle(handler)` to receive a column key and update the
row order in Roc.

For a complete report list example, see the Starter app and its specs described in
xref:apps.adoc#examples[Choose an example].

== Default actions and mixed check boxes

Set a button's `enter_action` to `WindowDefault` to submit from a
single-line field when Enter is available. A focused push button
retains its own action. Mount one default button per window.

`Ui.aggregate_checkbox` displays `Unchecked`, `Checked`, or `Mixed`
from a `state` signal. Activating it requests true from Unchecked or
Mixed and false from Checked. Use `on_change` to update the underlying
items and derive the aggregate state from them.

== Text labels and multiline values

`Ui.text(value)` wraps onto as many lines as needed. Use
`Ui.text_with(value, { overflow: EllipsizeEnd })` to keep a caption on one
line and show an ellipsis when it runs out of room. The control retains the
full caption for accessibility and behaviour specs.

`Ui.text_area(value, { label: "Contents" })` displays a read-only preview
that users can select, scroll and copy. Set `rows` to choose the visible
height. It defaults to five lines. Use `mode: Editable(on_input)` to receive
the complete draft after each edit. The value and handler use LF line
endings. Enter inserts a line break. Use a separate button to submit edits.

Echo the draft through the value signal to keep the displayed text and
the app's state in sync. If the value signal changes to a different string
while an editable area has focus, the native draft remains until focus
leaves. To reset the focused draft deliberately, set its `reference` and
issue `Engine.command(ApplyValue(reference))` from an effect plan in the
same turn as the new value. An active input method composition finishes
before the reset is applied.

[#data-grid]
== Editable data grids

Use `Ui.data_grid({ label, columns }, rows)` with `Engine.table_view` over a
typed table. Column widths and the visible-row budget follow report lists.
A grid can mount up to 1024 rows and 64 columns. Use the table view's window
to page larger datasets.

Build each row with `Ui.grid_row(cells)` and each cell with
`Ui.grid_cell(value, { column })`. Define one cell per column.
The default is read-only. An editable cell uses
`editor: TextEditor(row.set_value(apply_edit))`, for example.
The handler receives a `Ui.CellEdit` containing `draft`, the complete text.
Put validation in the Roc handler and pass a `feedback` signal of
`Clear` or `Invalid(message)`. An invalid edit can retain the committed
text and return feedback in the same write.

Use the arrow keys to move between cells and Enter or F2 to open the editor.
Enter commits an open edit. Escape or leaving the editor discards it.
The edit stays with its mounted cell when rows move and is discarded when
the cell leaves the window or its committed value changes.
The Workers example edits stock counts and reconciles a snapshot on a worker.

Hold Shift while moving with the arrow keys to extend a rectangular selection.
To handle Ctrl+V while the grid has focus, supply \`on_paste: Handle(handler)\`.
The handler receives \`Try(Ui.GridPaste, Ui.GridPasteError)\`. A successful batch
contains a one-based \`first_row\`, ordered column keys, and rows of values.
Resolve the batch against the same sort, filter and page used to display the
grid. Apply domain validation and changes in one Roc decision.

The clipboard accepts plain tab-separated text up to 64 KiB of UTF-16 data
and at most 64 rows by 32 columns. A single active cell is the top-left
corner for the pasted rectangle. A selected range must match the paste size.
A paste that exceeds the mounted rows, includes read-only cells or has
unequal line lengths returns a paste error before any cells change.
Ctrl+V in the open cell editor uses the native EDIT clipboard behavior.

[#native-styling]
== Native styling

`Ui.window` accepts an `appearance` record whose `accent` defaults to
`SystemAccent`. Supply `CustomAccent({ red, green, blue })` using three
`U8` channels for an app-specific accent. Owned dialogs inherit their
window's appearance. Windows contrast themes use the system colors.

`Ui.text_with` defaults to `Body` style, `PrimaryText` tone and `Start`
alignment. Other styles are `Caption`, `Heading`, `Title`, `Display` and
`Monospace`. `SecondaryText` de-emphasizes supporting labels, and
`AccentText` draws from the window accent with a readable foreground.
Alignment can be `Start`, `Center` or `End`. Start and end follow the
interface reading direction. Text wraps by default. Use `EllipsizeEnd`
for a single line that retains its full accessible caption.

`Ui.panel(props, content)` defaults to `Inset` surface, `NoBorder`,
12 DIP of padding and `Natural` width. Use `AccentTint` for a tinted
surface, `Outline` for a border, and `Fill` for the width available after
fixed-width siblings and gaps. A panel uses a single element as its
content. Use a stack inside it to group several controls.

See Counter for a centered display value and Reading List for a title and
an accent that carries across the app.

[#packaged-fonts]
=== Packaged fonts

`Ui.text_with` uses `SystemFont` by default. To use an app font, place a
single static TrueType face under `assets/`, declare it in
xref:apps.adoc#packaged-assets[the asset catalog] and define a text style
your views can share.

[source,roc]
----
count_style : Win.Ui.TextProps
count_style = {
	style: Display,
	align: Center,
	font: PackagedFont({
		asset: Win.asset("display-font"),
		family: "IBM Plex Sans",
		face: Bold,
	}),
}

readout = |count| Win.Ui.text_with(count, count_style)
----

`Ui.PackagedFontProps` defaults to `Regular` and also accepts `Bold`,
`Italic`, or `BoldItalic`. Use a separate asset for each face. The GDI
family name can differ from the filename and has a maximum of 31 UTF-16
code units. The text style supplies the size and fallback role. Windows
registers the font privately for the app process. The host verifies the
selected face against the file and uses the system role when the face
cannot be loaded or selected, or when the text needs complex shaping or
glyphs the packaged face lacks. Use a Windows system role for text
that regularly mixes scripts. The native label retains its full text as
its accessible name. Editors, commands, and other native controls keep
their system fonts.

The ordinary build, ZIP, and MSI asset flow carries the font. Check that
its license permits redistribution and keep the license text alongside
the file. Counter bundles IBM Plex Sans Bold and HTTP bundles IBM Plex
Mono Regular. Reading List and Workers show how to collect typography
and layout choices in app-owned theme records with system fonts.

[#raster-images]
== Raster images

Place PNG, JPEG (`.jpg` or `.jpeg`), and BMP artwork under `assets/`.
`Ui.asset_image(path, props)` resolves its path from that directory. Pass
an empty path to clear the picture. Use `fit: Contain` to center the
picture in the requested size while keeping its aspect ratio. The default
`Stretch` uses the full box. PNG alpha blends over the surrounding
surface, and JPEG orientation is applied before fitting.

To preview a picked or dropped `Engine.File`, issue `Ui.decode_image(file)`
with `Engine.watch_latest`. Keep the resulting `Ui.Raster` in app state.
Show it as `RasterImage(raster)` with `Ui.image`, or pass `NoImage` to clear
the surface. Use `Ui.raster({ width, height, rgba })` when the app already
has the pixels, such as a heatmap or rendered report page. Supply
8-bit, straight-alpha sRGB bytes in top-down, row-major RGBA order.
The decode path assumes sRGB for image colors.
The constructor checks the dimensions and requires exactly four bytes per
pixel. Images can be up to 8,192 pixels on either axis and 8,388,608
pixels in total. Encoded preview inputs can be up to 32 MiB.

Selected files remain opaque capabilities. The decoder passes an immutable
host-held raster by capability. App-produced RGBA crosses through a typed
binary attachment and is converted to premultiplied BGRA for presentation.
The Files example uses one decoded image in an ordinary view and in a
shader and supplies a second raster generated in Roc.

[#shader-views]
== Shader views

Use `Ui.shader_view({ description, shader, width, height, ... })` for one
Direct3D 11 pixel pass. Put precompiled shader-model 5.0 DXBC (`.cso`) in
the app's assets directory and reference it with `Win.asset(...)`. You
can build and run the Files example with its checked-in bytecode. If you
change the HLSL source, regenerate the bytecode from the example
directory. This command uses FXC on Windows.

[source,powershell]
----
fxc /T ps_5_0 /E main /Fo assets/scan-contrast.cso shaders/scan-contrast.hlsl
----

Roc builds and packages the checked-in shader asset on macOS, Linux and
Windows. The executable uses the Windows Direct3D 11 runtime.

The host supplies a full-screen triangle with normalized `TEXCOORD0`
coordinates from the upper left. Set `texture` for slot `t0` and
`second_texture` for slot `t1`. Either can be `NoTexture` (the default),
`AssetTexture(path)` or `RasterTexture(raster)`. The source spans UV 0–1
on each axis. The `s0` sampler clamps at the edges and defaults to
`Linear`. Use `Nearest` when exact texels matter. Sampled colors use
normalized sRGB-encoded channels and premultiplied alpha. Return color
in the same format for compositing.

Declare named scalar floats in one constant buffer at `b0`. Supply all
reflected values as `{ name, value: F32 }` records through the reactive
`parameters` prop. The host checks names, finite values and supported
bindings. A parameter change reuses the live texture. Windows uses a
hardware device where available and can fall back to WARP, then to the
unprocessed first texture or a visible diagnostic.

[#custom-surface-input]
== Surface input and sliders

`Ui.image` and `Ui.shader_view` default to `ReadOnly`. Use
`input: Interactive({ pointer, keys })` to opt into input. A `Pointer`
binding gives the zone a name and supplies the needed `down`, `move`,
`up` and `cancel` handlers. Choose `CaptureOnPress` to continue receiving
mouse reports during a drag outside the surface, and `LatestMove` for
the latest waiting move per frame. Coordinates are in 0–10000 inside the
zone. An outside report is `Outside`. A pending move is delivered before
the gesture ends.

`FocusedKeys({ key, handle })` opts the surface into focus traversal.
The host supports arrows, Home, End, Page Up and Page Down with a rendered
`Engine.Keymap`. A pointer-only surface can use a companion native
control for keyboard access.

`Ui.slider(value, { label, on_change })` uses an `I32` signal. Its
default range is `{ min: 0, max: 100 }` with a keyboard increment of 1.
Set `range` and positive `step` to change them. The handler receives a
requested position. Update the signal to commit the value. Use
`reference` with a `Focus` command to move focus to the slider when
a user drags its companion graphic.
