= Test and record Win32 apps

[#write-a-spec]
== Write a behaviour spec

Put one named `(test ...)` or `(demo ...)` form in each
`tests/specs/*.scm` file. Place input data under `tests/fixtures/`.
A spec can look up a control by its type and caption or accessible
label. This scenario adds and checks one item in the Starter app.

[source,scheme]
----
(test "mark a title read"
  (steps
    (fill (text-field "Title") "Roc guide")
    (click (button "Add"))
    (expect-row-selected (list-view "Titles") "Roc guide")
    (click (button "Mark read"))
    (expect-visible (text "0 unread"))))
----

Run `roc windows.roc -- test --check` to check source, run Roc expects,
and validate test and demo syntax. On a Windows desktop, use
`roc windows.roc -- test` to build the app and run each test against
a fresh process. Each failure names the spec and step. The CLI must match
the runner protocol in the platform bundle. On Windows on Arm, an x64 Roc
process can test an ARM64 build with `test --target arm64mingw`.

Selectors look up `button`, `checkbox`, `text-field`, `text-area`, `text`,
`file-button`, `folder-button`, `image`, `combo-box`, `list-box`, `radio-group`, `list-view`,
`date-picker`, `time-picker`, and `data-grid`.
Use `(within OUTER INNER)` to narrow a
selector to a row or container. An action needs a unique match. Use
`expect-text`, `expect-visible`, `expect-absent`, `expect-disabled` and
`expect-checked` to inspect the current control state. Keep control
assertions independent of pixel output. `text-area` finds a multiline
control by its visible label. `expect-text` compares the full text with LF
line endings. `fill` works on editable areas. Use `"first\nsecond"` for
multiline content.

Use `(select (combo-box "Status filter") "unread")` to propose a choice and
`(expect-selection (combo-box "Status filter") "unread")` to assert the current
selection. Both forms use the choice key. An empty string represents
no selection for a drop-down or list box.

For a report list, pass the locator and stable key to `select-row`,
`activate-row`, `press-column` or `expect-row-selected`. Pass an empty
string to `select-row` or `expect-row-selected` to clear or verify an empty
selection. Use `expect-list-rows` with the row keys in display order,
or with just the locator for an empty report.

Picker steps compare the native date and time fields across locales.
Use `no-date` and `no-time` to set or assert the unset state.
In the Todos app, clearing the due date also clears the due time.

[source,scheme]
----
(set-date (date-picker "New due date") (date 2028 2 29))
(set-time (time-picker "New due time") (time 9 15))
(expect-date (date-picker "New due date") (date 2028 2 29))
(expect-time (time-picker "New due time") (time 9 15))
(set-date (date-picker "New due date") no-date)
(expect-time (time-picker "New due time") no-time)
----

For an editable data grid, `focus-cell` and `begin-cell` take a grid,
a one-based mounted row number and a quoted column key. Use `fill-cell` with
the grid and a draft, then `commit-cell` or `cancel-cell` with the grid.
`expect-cell-focused` takes a row and column. `expect-cell-text` and
`expect-cell-feedback` also take the expected text. An empty feedback
string means the cell has cleared its error.

== Simulate and run effects

Tests start with isolated storage and hold HTTP requests, timers and
intervals by default. An optional `setup` form can seed
`local-storage` or `session-storage`, set `initial-time` in milliseconds,
or set a `worker-pool` limit. The HTTP example checks a submitted request
and answers it explicitly.

[source,scheme]
----
(expect-request 1 :method "GET" :url "https://example.test/guide")
(stub-http "guide" :status 200 :body "Read the guide.")
(run-effect 1)
(expect-visible (text "Read the guide."))
----

Held effects are numbered in issue order, starting at one. Use
`expect-pending-effects` and `expect-cancelled` to inspect them.
Use `fail-http` to stage a failure. Advance virtual time with
`advance-time` to exercise HTTP timeouts. Trigger a one-shot timer or
matching interval with `fire-timer` or `tick-interval`. Inspect a period
with `expect-interval`.

`(files "tests/fixtures/hello.txt")` supplies a file as a picker result.
Pass several paths to simulate a multi-file picker. The app reads or
hashes files through the production file adapter.
`(folder "tests/fixtures/photos")` supplies a directory to a folder picker
and runs the same bounded listing as a live selection. `(folder)`
simulates cancelling the dialog. Fixture paths are relative to the app.
`(await-work)` waits for file and Roc worker work to settle with a
real-time bound. Use `(setup (live-effects http))` to exercise the real
HTTP adapter or `(setup (live-effects time))` for real timers. Use a
loopback HTTP fixture for an integration test that can run independently.

Clipboard requests in a scenario use a private test clipboard.
`(expect-clipboard N "value")` checks the successful write count and last
text. `(clipboard-busy)` makes the next plain-text copy return
`Unavailable`.

== Capture a screenshot or record a demo

Use a Windows desktop session for capture. A
`(setup (window-size 640 520))` form sets client size. Use
`(screenshot "after-add")` for a PNG checkpoint or
`test --screenshot-on-failure` for a diagnostic image. Results are written
under `build/specs/`. Use a test's control assertions for repeatable
checks across themes and display settings.

A `(demo ...)` scenario uses real timing. It is validated with the test
suite and executed by the explicit `record` command. The starter's
`tests/specs/demo.scm` adds and marks an item.

[source,sh]
----
roc windows.roc -- record tests/specs/demo.scm --format gif
----

GIF is the default. Use `--format png` for frames. The artifacts are under
`build/specs/`. Recordings use the app's fixed-size window. Capture of
minimized, occluded, locked or noninteractive sessions requires separate
verification.

[#runner-boundary]
== Runner boundary

The CLI lowers a parsed scenario to a versioned plan file with source
locations. The built Win32 host executes that plan through its native
window, control and effect paths. Success requires an explicit completion
result. The runner uses separate storage per scenario and a watchdog that
still runs when the scenario uses virtual time.

Capture uses the app's window and child controls. GDI draws the window
into a bitmap. The installed Windows Imaging Component encodes PNG, and
the host encodes GIF on a separate thread. See
xref:architecture.adoc#redistributable-inputs[What the bundle contains].

== Check form actions

`(press-enter (text-field "URL"))` exercises the window's default-button
routing from that field. A disabled default leaves the current state
unchanged. Use `(expect-checked (checkbox "Complete all visible tasks") mixed)`
for a mixed aggregate check box.
